# Opportunity Framework

How to shape one specific, paid opportunity for each Pursue prospect.

---

## The Need Test (run first)

Before writing an opportunity, answer three questions with evidence:

1. **What's the moment?** A trigger with a date, from an Observed source.
2. **What's the gap or the opening?** Something observed that the studio's services address. Examples: the last anniversary ran only on drink specials; a launch date is announced with no programming yet; partners exist but aren't tied to a single idea.
3. **Why this studio?** A service in the context file that fits, and a verified proof point that makes the studio credible for it.

If any answer is "I imagine…" or "they probably…", the opportunity is a Hypothesis. Lower the tier, or turn it into a question for the first call.

---

## The Template

| Field | What goes here | Evidence tag |
|---|---|---|
| **Working title** | A short, specific name for the idea | — |
| **The moment** | Trigger and date | Observed |
| **The asset** | What the business already owns that the idea builds on (history, a signature item, a place, a ritual, existing partners) | Observed |
| **The idea** | One sentence, with a specific mechanic (a numbered run, a passport, a one-day exception, a collab item) | — |
| **The service** | The context-file service it uses (campaign development, activation, partnership strategy, merch or retail extension, pitch deck, naming, cultural positioning) | Context file |
| **Deliverable shape** | What the client would actually receive (for example, a concept deck with a rollout calendar and partner shortlist) | — |
| **Why now** | The timing evidence and lead-time reasoning | Observed + Inferred |
| **What would make it wrong** | The hypotheses that could sink it (they already have a plan, budget, a partner conflict) | Hypothesis |
| **Risks** | Brand, operational, or audience risks of the idea itself | Inferred |
| **How success could be judged** | Measures to agree with the client, using their own data. Label as illustrative. | — |

---

## Rules

- **One opportunity per prospect.** If several ideas come up, pick the strongest and note the others in one line.
- **Build from owned assets.** The best ideas extend what the business already has, rather than inventing a new identity.
- **Name the mechanic.** "An anniversary event" is a category. "A numbered collectible run sold only during anniversary week" is an idea.
- **Respect operating reality.** Size it to what the business's team can run.
- **Partners are proposed, not committed.** Say "proposed partner" for every named third party.
- **No ROI promises.** Never forecast revenue, covers, or traffic for the prospect. If a model helps the user think, label it "illustrative," keep it internal, and never put it in outreach.
- **No excluded services.** If the only way in is a do-not-pitch service, the prospect is a Skip.
- **No free work.** The opportunity is for the user's planning and the first call. Don't turn it into a deck, mockups, or a full concept unless the user asks after the prospect replies.
- **Pricing stays private.** If the private context holds confirmed pricing, note the likely scope band internally. Never put prices in outreach.

---

## Portfolio Proof in Opportunities

Use only the verified proof points in the context file. A portfolio concept (unsolicited work) may be cited only when:
- it's described accurately as a concept or proposal, never as client work, and
- the user has cleared it for public reference.

If either is unclear, leave it out.
